# Codex 飞书桥游客模式使用指南

## 1. 这是什么

Codex 飞书桥是一名运行在飞书中的 ERP 只读排查助手。

同事可以直接向机器人描述业务问题。机器人会在专属的 Codex 会话中，结合以下信息协助排查：

- 你有权限访问的 ERP 业务数据；
- 指定 ERP 项目的相关源码和业务逻辑；
- 你发送的文字、单据编号、SKU、报错信息和截图；
- 当前会话中此前的提问和回答。

游客模式只用于查询、核对和分析，不会修改源码、测试数据或线上数据。

## 2. 快速开始

在飞书中找到 Codex 机器人后，直接发送问题即可，不需要先输入 `/codex` 命令。

第一次提问时，系统会自动创建你的专属只读会话：

```text
自主排查@你的飞书姓名
```

后续消息默认继续进入这个会话，因此可以直接追问，不必重复全部背景。

### 第一次提问示例

```text
帮我查询 SKU G37007BR05A-YF 最近的有效采购记录，列出采购单号、状态、采购数量、已出运数量和剩余数量。
```

### 推荐的提问格式

尽量提供“对象 + 问题 + 时间范围 + 期望结果”：

```text
对象：订单号 SO202610290001
问题：订单已经付款，但一直没有进入待发货状态
时间范围：今天
期望结果：核对实际数据，并结合代码说明卡在哪个条件
```

信息越准确，排查速度通常越快。建议优先提供订单号、SKU、采购单号、平台、店铺、站点、报错时间等唯一信息。

## 3. 可以用来做什么

### 场景一：查询订单、商品或业务记录

可以查询本人 ERP 权限范围内的订单、SKU、商品、采购、库存、物流、售后等业务数据。

示例：

```text
查询订单 SO202610290001 当前的订单状态、付款状态、发货状态和最近更新时间，并说明是否存在异常。
```

```text
查询 SKU G37007BR05A-YF 在我负责店铺中的有效商品记录，列出平台、店铺、站点和当前状态。
```

机器人会尽量明确区分：

- **已由数据证实**：来自实际只读查询的结果；
- **根据代码推断**：根据 ERP 业务逻辑得出的判断；
- **尚未验证**：因为权限、条件或数据不足暂时不能确认的内容。

### 场景二：排查业务状态为什么没有流转

可以同时核对实际数据和源码中的状态流转条件，定位业务卡点。

示例：

```text
订单 SO202610290001 已经付款，但没有进入待发货。请先核对生产数据，再根据项目代码检查状态流转条件，告诉我是数据缺失、条件未满足还是任务没有执行。
```

```text
采购单 PO202610290001 已经审核，但状态仍然是计划中。请核对单据数据和审核流程代码，列出没有继续流转的具体条件。
```

### 场景三：查询采购记录和剩余数量

可以按 SKU、采购单号等条件查询采购记录，并进行只读汇总。

示例：

```text
查询 SKU G37007BR05A-YF 的有效采购明细，排除已删除记录，按采购单列出采购数量、已出运数量、取消数量、剩余数量和预计交期，并汇总总数。
```

如果问题涉及采购价、供应商等敏感数据，只有 ERP 权限中包含对应查看权限时才会返回。

### 场景四：核对库存、数量或统计口径

可以核对指定业务对象的数量，并解释统计口径和差异来源。

示例：

```text
核对 SKU ABC123 在美国站点的可用库存、占用库存和在途数量，说明页面显示数量与实际明细不一致的原因。
```

```text
统计我负责店铺 2026-10-01 至 2026-10-28 的有效订单数量，排除已取消和已删除记录，并说明使用了哪些过滤条件。
```

### 场景五：根据截图识别报错并排查

游客模式支持识别飞书中发送的图片。可以发送报错截图、页面截图或数据异常截图，并附上一句背景说明。

示例：

```text
这张截图是我今天 15:30 在采购单审核页面遇到的报错。请识别报错内容，结合代码和允许访问的数据分析原因。
```

如果只发送图片，机器人也会尝试识别；但同时提供页面、操作步骤、单据编号和发生时间，结果会更准确。

### 场景六：解释 ERP 功能和业务规则

可以根据项目源码说明字段含义、状态规则、计算公式和操作条件。

示例：

```text
请根据代码解释采购单的“计划中、采购中、已完成、已取消”分别在什么条件下产生，以及状态之间如何流转。
```

```text
页面上的“剩余数量”是怎么计算的？请给出参与计算的字段、排除条件和对应代码位置。
```

这类问题可能主要依据源码回答。机器人会标注哪些内容属于代码规则，避免把代码推断误认为线上实际数据。

### 场景七：定位数据异常的可能原因

可以从数据、代码条件和任务流程三个方向交叉排查。

示例：

```text
SKU ABC123 在商品列表中存在，但创建采购单时搜索不到。请核对商品状态、权限范围和代码中的筛选条件，按可能性列出原因，并说明哪些已经由数据证实。
```

```text
订单 SO202610290001 在 ERP 中显示已发货，但平台仍显示未发货。请检查相关数据和同步逻辑，判断是数据问题、同步任务问题还是平台返回异常。
```

### 场景八：验证某项业务结论

可以让机器人验证同事、报表或页面给出的结论是否与实际数据一致。

示例：

```text
同事说 SKU ABC123 还有 51 件未出运。请使用生产只读数据重新核对，列出计算明细，并明确结论是否正确。
```

```text
页面显示该订单利润为负数。请核对当前权限允许查看的相关字段和代码计算公式，说明负数由哪些项目造成。
```

### 场景九：导出 Excel、CSV 或 Word 文件

需要批量明细时，可以在问题中明确写出导出格式和字段。机器人会先执行权限校验和数据脱敏，再把文件发送到当前飞书聊天。

Excel 示例：

```text
查询 SKU G37007BR05A-YF 的有效采购明细，并导出 Excel。字段包含采购单号、状态、采购数量、已出运数量、剩余数量和预计交期。
```

CSV 示例：

```text
导出我负责店铺 2026-10-01 至 2026-10-28 的有效订单 CSV，字段包含订单号、平台、店铺、订单状态和下单时间。
```

Word 示例：

```text
把刚才的异常分析整理成 Word 文档，包含问题现象、数据证据、代码判断、可能原因和处理建议。
```

导出仍遵循 ERP 权限：没有查看权限的数据不能通过导出绕过。单次导出还受行数和飞书附件大小限制。

### 场景十：在同一个问题上连续追问

同一个会话会保留上下文，可以直接要求补充、筛选、汇总或改变展示方式。

示例对话：

```text
你：查询 SKU G37007BR05A-YF 的采购记录。

你：只保留未完成的采购单。

你：再按站点汇总剩余数量。

你：把最终明细导出成 Excel。
```

如果开始完全不同的主题，建议使用 `/new`，避免旧上下文影响新问题。

### 场景十一：开始一个全新的会话

发送：

```text
/new
```

系统会创建并切换到一个新的专属只读会话。旧会话仍保留在 Codex Desktop 历史中，但游客不能查看会话列表或任意切换会话。

如果当前任务还在执行，系统会提示先停止任务，避免产生无法管理的后台任务。

### 场景十二：停止当前任务

当问题不再需要继续、查询范围填错或任务执行时间过长时，发送：

```text
/stop
```

示例：

```text
刚才的时间范围写错了，先发送 /stop；任务停止后再发送正确的问题。
```

`/stop` 只停止你当前会话中的任务，不会影响其他同事的任务。

## 4. 权限和安全边界

游客模式严格复用 ERP 身份和角色权限。机器人会将飞书用户映射到 ERP 用户，再校验角色、模块和数据范围。

### 你可以访问

- 自己 ERP 角色有权查看的业务模块；
- 自己负责的平台、店铺、站点和品类范围内的数据；
- 与允许访问模块相关的指定 ERP 项目源码；
- 经过脱敏和行数限制的查询结果及导出文件。

### 你不能访问

- 不属于本人角色或负责范围的数据；
- 管理员或其他同事的 Codex 会话；
- 指定 ERP 项目目录以外的本机文件；
- 手机、邮箱、详细地址、账号凭据、银行账户等禁止字段；
- 没有相应细粒度权限的采购价、供应商等敏感信息；
- 任意数据库写入、源码修改、Shell 命令或线上操作。

超出权限时，机器人会回复：

```text
无权访问
```

不要尝试通过改写问题、要求执行 SQL 或要求导出文件绕过权限，所有查询和导出使用同一套权限校验。

## 5. 怎样获得更准确的结果

### 建议这样提问

- 提供准确的订单号、SKU、采购单号等唯一标识；
- 说明平台、店铺、站点或业务模块；
- 提供明确的时间范围；
- 描述预期结果与实际现象；
- 要求机器人区分“数据证实”和“代码推断”；
- 需要文件时明确格式、字段和筛选条件；
- 截图排查时补充页面名称、操作步骤和发生时间。

完整示例：

```text
请排查订单 SO202610290001 为什么付款后没有进入待发货。

范围：美国站点、我负责的店铺，问题发生在 2026-10-29 14:20 左右。
要求：
1. 先核对生产只读数据；
2. 再检查相关状态流转代码；
3. 分开列出已由数据证实、根据代码推断和尚未验证的内容；
4. 给出下一步处理建议，不要修改任何数据。
```

### 不建议这样提问

信息过少：

```text
为什么不对？
```

范围过大：

```text
把所有订单都查出来。
```

要求越权操作：

```text
帮我修改这条线上数据，或者把其他部门的数据全部导出。
```

## 6. 如何理解机器人回复

任务执行时，飞书会持续更新进度卡片，展示公开的分析摘要、计划和工具状态。任务结束后，会另外推送最终结果，消息标题会包含当前会话名称。

常见结果包括：

- **查询成功**：返回实际数据、汇总和分析结论；
- **无权访问**：ERP 角色或数据范围不允许访问目标内容；
- **条件不足**：需要补充单据编号、时间范围、平台或店铺；
- **仅能代码推断**：当前没有足够数据证据，但可以说明代码规则；
- **任务已停止**：收到 `/stop` 后终止当前任务；
- **文件附件**：导出成功后发送 Excel、CSV 或 Word 文件。

## 7. 常见问题

### 为什么别人能查到，我却显示“无权访问”？

每个人使用自己的 ERP 身份和角色权限。即使提问内容相同，不同角色、模块、店铺或品类范围也可能得到不同结果。

### 机器人会修改线上数据吗？

不会。游客模式使用生产只读连接，并关闭了数据库写入、源码修改和命令执行能力。

### 我能查看其他同事的会话吗？

不能。游客无法列出项目或会话，也不能切换到管理员或其他同事的会话。

### 新问题是否都要发送 `/new`？

不需要。同一业务问题建议连续追问；只有开始完全不同的主题，或者希望清空旧上下文影响时才使用 `/new`。

### 为什么图片没有得到准确结果？

截图可能缺少单据编号、完整报错或业务背景。请补充页面名称、操作步骤、发生时间和相关业务编号。

### 为什么导出没有包含某些字段？

可能是该字段属于敏感信息、本人没有对应权限，或该字段未包含在明确的导出要求中。机器人不会为了导出而放宽权限。

### 机器人结果可以直接作为最终业务结论吗？

对于重要决策，应优先参考回复中“已由数据证实”的部分，并由业务负责人复核。仅依据代码推断或信息不足的内容，不应当作已验证事实。

## 8. 快捷指令

| 指令 | 作用 | 使用示例 |
|---|---|---|
| `/new` | 新建并切换到自己的只读排查会话 | 开始一个与当前问题无关的新主题 |
| `/stop` | 停止当前会话正在执行的任务 | 查询条件写错或不再需要继续执行 |

除这两个快捷指令外，游客通常只需像普通聊天一样直接描述问题。
